## 1. Что такое Dreem World

**Dreem World** — кроссплатформенное приложение (Android / iOS / Web) на Flutter.
Актуальная реализованная концепция: **«галактика интересов»** — неоновый социальный
продукт, где интересы представлены планетами-сообществами. Пользователь исследует
планеты, входит во внутренний мир планеты, смотрит карту, новости, подбирает людей по
совместимости, общается в чатах. Есть темы оформления, безопасность/модерация,
внутриигровая валюта, подписка Dreem+.

Слоган раннего концепта: **«Connect. Understand. Belong.»**

### Аудитория и цель (требует уточнения в деталях)
- Позиционирование: знакомства и общение по интересам/совместимости с помощью ИИ.
- Точная целевая аудитория, монетизация и метрики успеха — **требует уточнения**.

## 2. Технологический стек

| Область | Решение |
|---|---|
| Язык / фреймворк | Flutter (Dart, SDK `^3.13.5`) |
| Управление состоянием | Riverpod (`flutter_riverpod`) |
| Навигация | go_router |
| Модели | freezed + json_serializable (+ build_runner) |
| Утилиты | equatable, uuid, intl, collection |
| Локальное хранилище | shared_preferences, flutter_secure_storage |
| Медиа | image_picker |
| Визуал | flutter_animate, кастомпроцедурная галактика, `flutter_map` |

> автоматически остаётся в мок-режиме без сети. Подробности — раздел 27.

### Навигация (go_router) — подтверждено кодом
- Публичные маршруты: `/login`, `/register`, `/onboarding`, `/splash`.
- `redirect` зависит от `authControllerProvider` и `hasSavedProfileProvider`.
- Оболочка `StatefulShellRoute.indexedStack` с 4 вкладками:
  `/main` (главная-планеты), `/discovery`, `/chats`, `/contacts`.
- Вложенные: `/main/planets`, `/main/other-interests`, `/main/planet/:id`,
  `/main/planet/:id/map`, `/main/planet/:id/news`.
- Полноэкранные: `/profile`, `/settings`, `/safety`, `/minigames`, `/chat/:id`, `/match`.

## 4. Ключевые текущие фичи (реализовано в коде)

- **Главная (PlanetHomeScreen)**: солнце в центре и планеты, профиль, уведомления, меню.
- **Каталог «Все планеты»**: орбитальный каталог (`OrbitalCatalog`) с 22 планетами-сообществами.
- **Планета-сообщество**: `Planet` + `PlanetScene` (24 сцены: fishing, travel, cinema, books,
  music, sports, reading, art, technology, food, nature, gaming, cars, animals, gardening,
  esoteric, finance, volunteering, psychology, other, selfDevelopment, collecting, space, …).
- **Карта внутреннего мира планеты**: отметки, теги, комментарии (`MapSpot`).
- **Лента новостей планеты** с ежечасным обновлением (`PlanetNews`).
- **Подбор (Discovery)** с процентом совместимости и статусом отношений.
- **Мэтч**, **чаты** (подвкладки Все / По интересам / Непрочитанные), заблокированный видеовызов.
- **Контакты и поиск по ID**: у каждого пользователя постоянный код `DW-XXXX-XXXX`,
  поиск по нему находит анкету и добавляет человека в контакты (QR-коды удалены).
- **Кошелёк**: валюта за входы + мини-игра «Колесо удачи».
- **Dreem+** — карточка подписки (демо, оплата не подключена).
- **Безопасность**: жалобы, ИИ-фильтр, блокировки, возрастной контроль, Центр безопасности.
- **Аутентификация**: регистрация и вход по email/паролю через Firebase, письмо с
  подтверждением почты от Google, отдельный экран ожидания подтверждения с повторной
  отправкой, восстановление пароля. Без параметров Firebase — безопасный откат на мок-режим.
  Google/Phone в слое сервисов **не реализованы** (требует уточнения приоритета).
- **Темы**: неоновые темы оформления + глобальный космический фон с Млечным Путём.

### Проблема раскладки OrbitalCatalog (текущая задача)
- Экран «Все планеты» на **ПК**: планеты наслаивались, нижняя планета обрезалась.
- Решение (задеплоено): размеры планет/солнца считаются от **меньшей стороны** области
  (`min(w, h)`), орбиты растягиваются по ширине, размер планеты ограничен шагом по дуге,
  углы колец чередуются.
- **Экран телефона** для этой задачи **отложен** (делаем позже) — по решению пользователя.
- Остаточный статус: **на проверке пользователем** (нужен Ctrl+F5). Если проблема остаётся —
  смотреть заново геометрию и фактическую высоту области под заголовком.

## 6. Принятые решения и ограничения окружения

- **Язык интерфейса и кода — русский.**
- **Android SDK локально отсутствует** → APK только через GitHub Actions.
  iOS собирается только на macOS.
- Пуш иногда падает `Recv failure: Connection was reset` — ретраить.
- Модель (агент) **не читает изображения**; визуал — процедурный, с авто-подхватом PNG:
  `assets/planets/<id>.png` (×22) и `assets/space/sun.png` через `Image.asset` + `errorBuilder`.
  Реальные PNG от пользователя **пока не предоставлены** (папки ждут файлов).
- **Firebase** реально настроить нельзя без логина пользователя в Google (отложено).
- **`edit` к `orbital_catalog.dart` иногда откатывается** — писать файл целиком.
- **Не выполнять `git push` / публикацию без явного разрешения.**
- Синхронизация: пользователь работает с GPT на телефоне; GPT даёт **текстовые промты**;
  изменения в репозиторий вносит только локальный агент.

## 8. Идея галактики с движущимися планетами и исследованием сцены

Зафиксированная идея (для будущей реализации, **ещё не реализована**):

- **Галактика интересов с движущимися планетами**: планеты-сообщества не статичны,
  а движутся по орбитам/дрейфуют; сцена «живая».
- **Интерактивное исследование сцены**: пользователь может свободно исследовать
  космическую сцену — приближать/отдалять, перетаскивать, выбирать планету,
  «влетать» в её внутренний мир (карту, новости, сообщество).
- Планеты = интересы/направления (активный образ жизни, путешествия, творчество,
  дружба, семья, саморазвитие и др.).
- Возможная связь с функцией «Галактика возможностей» из архивного макета.

**Требует уточнения:** конкретная механика движения (орбиты/физика), объём интерактива,
нужен ли отдельный режим-«карта галактики» или интеграция в существующий `OrbitalCatalog`.

## 30. Реальные участники планет и чат между аккаунтами (16.11.2026)

  Запись идёт через существующее правило «пользователь меняет только свою анкету»,

### 30.1. Автосоздание анкеты и честные ошибки (17.11.2026)

- **Причина сбоя вступления после публикации правил.** Коллекция `profiles` в Firestore
  была пустой: после регистрации приложение ведёт сразу на `/main`, экран заполнения
  анкеты не открывается, поэтому `getCurrentProfile()` возвращал `null` и
  `PlanetMembershipController.toggle` бросал `StateError('Анкета не найдена')` — на экране
  планеты это выглядело как «Не удалось вступить. Попробуйте ещё раз». С rules это не
  связано: rules разрешают пользователю писать свою анкету (проверено REST-запросом).
- **Исправление.** Новый `profileBootstrapProvider` (`app_providers.dart`) при входе
  гарантирует наличие анкеты в Firestore: если её нет — создаёт с именем из аккаунта
  регистрации (возраст 18), если есть — синхронизирует облако с локальной копией. Провайдер
  наблюдается в `AppShell`, поэтому срабатывает сразу после входа, на сайте и в APK.
- **Запасной путь.** `toggle` больше не падает без анкеты: если её всё равно нет, создаёт
  профиль из аккаунта (`currentUserFromAuthProvider`) и сразу вступает. После успешной
  записи вызывается `ref.invalidate(currentProfileProvider)`, поэтому кнопка мгновенно
  становится «Вы уже присоединились».
- **Честные ошибки.** `FirestoreProfileRepository.saveProfile` теперь пробрасывает ошибку
  записи (с `debugPrint`), а экраны анкеты (`ProfileSetupScreen`, `ProfileViewEditScreen`)
  показывают снекбар «Не удалось сохранить…» вместо ложного успеха. В мок-режиме поведение
  прежнее (218 тестов проходят).

### 30.2. Починка чата и списка участников (17.11.2026)

- **Почему чат не открывался.** В правилах Firestore чтение диалога разрешено только
  участникам (`request.auth.uid in resource.data.participantIds`). Для **несуществующего**
  документа `resource.data` пуст, поэтому чтение отклоняется с `permission-denied`, а
  `FirestoreChatRepository.getOrCreateConversation` ждал от `reference.get()` «документа
  нет» и пробрасывал 403 наружу. Внешне это выглядело как «Не удалось открыть чат.
  Попробуйте ещё раз» (проверено REST-запросом: `GET` несуществующего диалога — 403,
  `create` и последующее чтение — 200).
- **Исправление чата.** `getOrCreateConversation` теперь ловит отказ на чтении и трактует
  его как «диалога ещё нет», после чего создаёт документ (`create` правилами разрешён).
  Настоящие ошибки (сеть, запись) по-прежнему пробрасываются наверх и показываются снекбаром.
  Дополнительно `_MemberTile._openChat` обёрнут в `try/catch` со снекбаром — раньше исключение
  было необработанным.
- **Почему список участников был белым.** Плитка участника (`_MemberTile`) — это
  `GlassCard` (`BackdropFilter`) внутри `flutter_animate`-анимации прозрачности. На web
  (CanvasKit) связка «`BackdropFilter` под анимацией `Opacity` поверх анимированного фона
  сцены планеты» рисуется сплошным белым прямоугольником, а белый текст на белом фоне
  невидим. Поэтому карточки выглядели как «белое окно» без участников.
- **Исправление списка.** `GlassCard` теперь пропускает `BackdropFilter`, когда `blur <= 0`
  (и повышает непрозрачность фона до 0.9/0.72, чтобы текст читался без размытия), а плитка
  участника использует `blur: 0` и рендерится без входной анимации. Остальные карточки
  приложения (поиск, новости, вход) не затронуты.
- **Заявки в друзья не реализованы.** В коде нет ни коллекции заявок, ни экрана
  «Принять/Отклонить»: кнопка «Добавить в контакты» лишь добавляет ID в локальный список
  контактов (`ContactsController`, в памяти) и не уведомляет второго пользователя. Для
  полноценных заявок нужна новая коллекция Firestore и **ручная публикация новых правил**
  в консоли. Требует отдельного решения пользователя.
- **Проверки (17.11.2026):** `flutter analyze` — `No issues found`, `flutter test` — 218
  тестов, `flutter build web --release --base-href "/DreamWorld/" --pwa-strategy=none` —
  успешно.

### 30.3. Нижняя навигация на web, счётчик непрочитанных и уведомление о сообщении (17.11.2026)

- **Почему пропала нижняя навигация и был «серый прямоугольник».** Нижняя панель
  (`AppNavigationBar`) и верхняя (`NeonAppBar`) рисовались через `BackdropFilter`
  (`ImageFilter.blur`). На части устройств и браузеров (особенно web на программном
  WebGL / Android Chrome) размытие фона не поддерживается и рисуется сплошной серый
  прямоугольник — из-за него «исчезала» полоса вкладок Планеты/Поиск/События/Чаты/Контакты,
  а секция участников планеты выглядела серым блоком.
- **Исправление на web.** В `GlassCard`, `AppNavigationBar` и `NeonAppBar` размытие
  отключается на web (`kIsWeb`) и включается плотный фон без `BackdropFilter`
  (нижняя панель — `Color(0xFF0A1B33)`, верхняя — чёрный с alpha `0.72`); на мобильных
  «матовое стекло» сохранено. У `GlassCard` условие `frosted = blur > 0 && !kIsWeb`.
- **Счётчик непрочитанных.** `AppNavigationBar` стал `ConsumerWidget`: на вкладке «Чаты»
  показывается `Badge.count` с суммой `unreadCount` по всем диалогам
  (`conversationsProvider`).
- **Уведомление о новом сообщении.** `AppShell` подписан на `conversationsProvider`
  (`ref.listen`) и при росте непрочитанных показывает снекбар «Новое сообщение: <текст>».
  Это работает, **пока приложение открыто**; настоящие push-уведомления при закрытом
  приложении требуют FCM и серверной части — вне текущего объёма.
- **Отметка «прочитано».** `ChatScreen` вызывает `markAsRead` при открытии диалога и при
  появлении новых сообщений (`ref.listen(messagesProvider(...))`), поэтому счётчик
  сбрасывается, когда чат открыт.
